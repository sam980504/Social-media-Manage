講話用白話，一次只問一個問題，不要叫使用者填表。

1. 執行 `python3 tools/social.py overview`，把結果整理成一張白話表給使用者：每個角色的狀態、有幾篇草稿等他核准、下一篇什麼時候發、有沒有 token。主動點出需要他動手的（有草稿待審、有發佈失敗、角色還沒確認）。成效數字不要跨角色比大小。
2. 有角色時，問使用者：繼續哪一個，還是建立新的？沒有角色就直接進建立。
3. **繼續既有角色**：記下代號，之後所有指令都帶 `--account <代號>`，所有檔案都讀寫 `accounts/<代號>/`。依狀態接續：
   - persona 未確認 → `set-persona`
   - 風格還沒定 → `set-style`
   - 都有了 → 看使用者要做什麼（`draft-posts`、`research-topics`、`review-performance`…）
4. **建立新角色**：
   - 問使用者想叫它什麼代號（小寫英文、數字、連字號，例 `ai-hype-tsukkomi`）。
   - `python3 tools/social.py init-account <代號>`，得到空白資料夾（沒有預設風格、沒有範本內容）。
   - 接著走 `set-persona`，再走 `set-style`。

## 獨立性規則
- 每個角色的設定、風格、研究、學習、成效、貼文檔、token 都只在自己的資料夾，不得讀另一個角色的資料來用。
- 同一段對話裡切換角色時，要明講「現在換成 <代號>」，並重新讀該角色的 persona.md、brand-guide.md、user.md 和 strategy.md，不要沿用上一個角色的語氣或結論。
- 不確定現在在處理哪個角色時，先問使用者，不要猜。
