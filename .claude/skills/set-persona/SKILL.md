以下的 `<代號>` 是正在處理的角色資料夾名。不知道是哪個，先走 `start`。

## 原則
- **每次都訪談，不提供現成範本**，也不要把別的角色的設定當預設答案。
- 用白話聊，**一次只問一個問題**，不要叫使用者填表。使用者隨便講，由你整理進檔案。
- 每問完一題，就把答案寫進對應欄位（身分、受眾、邊界 → `accounts/<代號>/persona.md`；聲音、禁用詞、範例貼文 → `accounts/<代號>/brand-guide.md`；使用者提到的審核習慣、方便審核的時間 → `user.md`），並標註「使用者親口說的」。使用者沒講的欄位留空，不要替他補。
- 「真實背景」只寫使用者親口說的事實，不可替他編造經歷。虛構角色必須標明是角色帳號。

## 流程
1. 讀 `accounts/<代號>/persona.md`，用一兩句話說目前角色是什麼（空白就明說）。
2. 照順序一次問一題（可以依使用者的回答調整順序）：
   1. 這個帳號主要想講什麼？
   2. 如果它是一個人，在朋友聚會裡是什麼樣子？
   3. 這個領域裡最讓他翻白眼的是哪種場面？（決定吐槽對象或內容重心）
   4. 使用者自己的真實背景是什麼？（做什麼、做多久）
   5. 貼文裡要不要點出公司或身分細節？（提醒公司規定與代表公司發言的風險，建議只寫職稱）
   6. 這個帳號要經營哪些平台？（目前支援 threads、bluesky，可複選；寫入 `platforms.md` 的 `platforms:`，沒有預設值，各平台憑證之後由使用者自己放進 `.env`，不要請他貼給你）
   7. 有沒有絕對不碰的題材？（先提醒常見雷區：政治、宗教、人身攻擊、點名個別公司或個人、投資理財建議，問要保留哪些）
3. 材料夠了就**直接寫一篇試稿**給使用者看，問像不像。依回饋微調，直到使用者說「對，就是這個味道」，才把 status 改為「已確認」。
4. 確認後，把使用者認可的試稿放進 brand-guide.md 的範例貼文。
5. 同步更新 `accounts/<代號>/strategy.md` 第 1 節的主題與受眾，並在 `accounts/<代號>/changelog.md` 記一筆。
6. 角色變更是大改動：變更後成效與舊資料不可比，請在 changelog 標註日期，檢討時分段看。
7. 下一步接 `set-style`。
